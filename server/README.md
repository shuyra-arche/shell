# Shell server library

This directory is an independent library workspace inside the Shell
repository. It contains the Shell server library (`shell-server`), the Lisp
REPL, the native host, the startup handshake, and the job/pipe adapters from
`anreonyr/sqware` at `94e114614bec53424ac55e640fc80cf19a3e7107`. The source
bodies are the original bodies; this slice changes only the crate header,
module locations, and dependency paths.

`shell-server` is a `#![no_std]` library with `extern crate alloc`. It is not a
workspace member of the root interface workspace and does not change the root
manifests. It consumes the sibling `lisp` crate by path (`../lisp`); all other
dependencies are the Source baseline full-SHA HTTPS GitHub pins recorded in
`Cargo.toml`. It has no Git dependency on Lisp and no system-support or mold
direct dependencies.

## Ownership and dependencies

- `shell-api` (`../api`) and `shell-declaration` (`../declaration`) are path
dependencies from this repository.
- `lisp` (`../lisp`) is the language library imported from the Source baseline.
- `env`, `resource`, `execution`, `ipc`, `pipe`, `system`, `terminal`,
  `stream`, and `wire` remain pinned to the Source commits recorded in
  `Cargo.toml`.
- No root `Cargo.toml`, root `Cargo.lock`, `api`, `client`, `declaration`, or
  `lisp` source is modified by this slice.
- Commands, the generic image runtime, and `programs::entry` are not added
  here; this slice does not duplicate them.

## Original tests

The `tests/shell` and `tests/shell-adapter` members are the original Source
test crates with only their standalone workspace markers removed and their
source `#[path]`/`include!` strings and `lisp`/`shell-api` dependency paths
adjusted to this tree. Fixtures and assertions are otherwise unchanged. The
test crates are separate workspace members and their manifests import the
sibling packages by relative path.

Four original Python scripts are retained byte-identical from the Source
test tree and are not run by this slice. Fixture locks are retained and
ignored; the effective `server/Cargo.lock` is generated by the executor and
committed separately.

## Build and test

Host tests use explicit packages and target:

```sh
cd server
cargo test --locked -p shell-tests -p shell-adapter-tests --target x86_64-unknown-linux-gnu
```

Full runtime builds for RISC-V, debug and release:

```sh
cd server
cargo build --locked --target riscv64gc-unknown-none-elf
cargo build --locked --release --target riscv64gc-unknown-none-elf
```

`--locked` applies after the executor has generated `server/Cargo.lock`.
These commands are the intended verification; results are recorded by the
executor, not claimed here.

## Deferred boundaries

The actual entry ELF, Source baseline integration, Vanllia composition, SMP,
and QEMU runtime verification remain deferred and are not claimed to have
passed by this slice. The `lisp` crate is consumed here as a library only;
entry-level and system image behaviour remain outside this directory.
